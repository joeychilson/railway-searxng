# SearXNG on Railway

[![CI](https://github.com/joeychilson/railway-searxng/actions/workflows/ci.yml/badge.svg)](https://github.com/joeychilson/railway-searxng/actions/workflows/ci.yml)
[![Release](https://img.shields.io/github/v/release/joeychilson/railway-searxng)](https://github.com/joeychilson/railway-searxng/releases/latest)
[![License: MIT](https://img.shields.io/badge/License-MIT-blue.svg)](LICENSE)

A Railway template for running a private
[SearXNG](https://github.com/searxng/searxng) metasearch instance optimized for
LLM and agent tools.

## Deployment

[![Deploy on Railway](https://railway.com/button.svg)](https://railway.com/deploy/searxng-api?referralCode=NhCCIt&utm_medium=integration&utm_source=template&utm_campaign=generic)

The template provides:

- A plain GET JSON search API.
- A pinned and smoke-tested SearXNG image for AMD64 and ARM64.
- Curated general, developer, package, and academic search engines.
- An eight-second engine timeout with one retry.
- A `/healthz` Railway healthcheck.
- Private Railway networking without Redis or Valkey.

`SEARXNG_SECRET` is required and generated by the template. The service refuses
to start without it.

The template does not create a public domain. SearXNG has no application
authentication, and this configuration disables its rate limiter. Keep the
service private unless unrestricted public access is intentional.

Services in the same Railway project can connect to:

```text
http://searxng.railway.internal:8080
```

To expose the service outside Railway, attach a public domain to port `8080`.
Anyone with that URL can query the instance.

## Configuration

| Variable | Required | Purpose |
|---|---|---|
| `SEARXNG_SECRET` | Yes | Server-side secret key |
| `SEARXNG_BASE_URL` | No | Public instance URL, including the trailing slash |

SearXNG reads both variables directly. The secret is intentionally excluded
from `settings.yml`.

## API

Run a general web search:

```text
curl "http://searxng.railway.internal:8080/search?q=python+async&format=json"
```

Developer engines use the `it` category, while academic engines use
`science`:

```text
curl "http://searxng.railway.internal:8080/search?q=tokio+channels&format=json&categories=it"
curl "http://searxng.railway.internal:8080/search?q=mixture+of+experts&format=json&categories=science"
```

Target specific engines or use a bang shortcut:

```text
curl "http://searxng.railway.internal:8080/search?q=transformers&format=json&engines=arxiv,github"
curl "http://searxng.railway.internal:8080/search?q=%21gh+railway+cli&format=json"
```

Paginate or limit results by time range:

```text
curl "http://searxng.railway.internal:8080/search?q=rust&format=json&pageno=2&time_range=week"
```

The JSON response includes `results`, `answers`, `infoboxes`, and
`suggestions`. Each result includes its URL, title, content, engine, and score.

For an agent tool, expose a required `query` field with optional `categories`
and `time_range` fields.

## Search engines

| Category | Engines |
|---|---|
| General | DuckDuckGo, Brave, Qwant, Mojeek, Wikipedia, Wikidata, Currency |
| Developer | GitHub, GitLab, Stack Overflow, MDN, Hacker News, Arch Linux Wiki |
| Packages | npm, PyPI, crates.io, pkg.go.dev, Docker Hub |
| Science | arXiv, Semantic Scholar, Crossref, PubMed |

Google, Bing, Yahoo, Yandex, and Baidu are disabled because they commonly
block datacenter traffic or add unreliable latency. General web engines may
still reject cloud IPs intermittently; use `/stats` to inspect per-engine error
rates.

## Updates

SearXNG publishes rolling date-based images rather than stable releases. This
repository pins an exact upstream tag in the `Dockerfile`, and a weekly
workflow opens a pull request when a new tag is available.

Images are published only from GitHub releases. Exact `X.Y.Z` and
`sha-<commit>` tags are immutable, while `X.Y` tracks the latest patch release
in that minor line. There is no `latest` tag. The Railway template uses `X.Y`
so reviewed upstream updates can arrive through Railway image auto-updates.

Routine upstream updates use patch releases. Changes to template behavior,
variables, engines, or settings use a minor or major release so they do not
reach existing deployments automatically. The wrapper version is independent
from SearXNG; see [RELEASING.md](RELEASING.md) for the release policy.

## Development

```text
docker build -t railway-searxng:test .
./test/smoke-test.sh railway-searxng:test
```

Run the image locally:

```text
docker run --rm \
  -e SEARXNG_SECRET="$(openssl rand -hex 32)" \
  -p 8080:8080 \
  railway-searxng:test
```

The smoke test verifies the healthcheck, curated engine configuration, disabled
default engines, and a valid JSON search response over GET.
